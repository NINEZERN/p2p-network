# Взаимодействие человека и компьютера — Mgła

## Цель и аудитория

Снизить порог входа в приватное общение и дать пользователю возможность обращаться к разработчику без email. Основная аудитория — начинающие пользователи P2P; вторичная — разработчик поддержки. Базовые задачи: подключиться, пригласить собеседника, отправить сообщение/файл, получить ответ на обращение. Все ключевые действия доступны из постоянного бокового меню, а главная страница предлагает три явных следующих шага.

## Пользователь ↔ разработчик

| Ситуация | Действие пользователя | Действие разработчика | Обратная связь интерфейса |
|---|---|---|---|
| Непонятно, как начать | Открыть первые шаги / FAQ | Подготовленная справка | Пошаговая инструкция, объяснение состояний |
| Техническая ошибка | Создать тикет с шагами воспроизведения | Взять в работу, уточнить детали | Статус «В работе», история сообщений |
| Вопрос о функциях | Выбрать категорию вопроса | Ответить в тикете | «Есть ответ», индикатор в меню |
| Предложение улучшения | Описать идею | Обсудить идею в переписке | Сохранённый диалог |
| Проблема доступности | Выбрать соответствующую категорию | Уточнить устройство/барьер | Ответ в том же канале |
| Проблема приватности | Тикет соответствующей категории | Дать ответ/инструкцию | Пояснение ограничений, не отправлять секреты |
| Жалоба на злоупотребление | Создать жалобу | Рассмотреть вручную и ответить | История и статус; автоматическая блокировка не реализована |
| Недостаточно информации | Дополнить тикет | Задать уточняющий вопрос | Ответы обеих сторон с датой |
| Вопрос решён | Закрыть обращение | Ответить или закрыть | Статус «Закрыт» |
| Решение не помогло | Открыть повторно, написать | Продолжить диалог | Возврат в «Открыт», история остаётся |
| Качество помощи | Оценить от 1 до 5 | Видеть оценку в API | Сохранённое значение, выделенные звёзды |
| Вернуться позже/с другого устройства | Ввести сохранённый ключ | Не требует ручного восстановления | Свои обращения по тому же ключу |
| Узнать об изменениях | Открыть новости | Статическое объявление релиза | Описание реализованных возможностей |

Асинхронные тикеты, FAQ, объявления и оценки покрывают основные сценарии учебного проекта. Email, звонки, push-уведомления, вложения к тикетам, публичное голосование за идеи, SLA, удаление обращений и автоматическая модерация не реализованы. «Абсолютно все» взаимодействия нельзя исчерпывающе реализовать в одном прототипе: новые сценарии следует выявлять пользовательским тестированием.

## Состояния и предотвращение ошибок

- Сеть: не подключено → запрос → подключено; ошибка API объясняется текстом, повторная попытка доступна через кнопку подключения.
- Комната: нет комнаты → ожидание → установка канала → соединено / прервано / ошибка. Для повторного соединения выйти и создать/открыть комнату заново.
- Сообщения и файлы недоступны до открытия DataChannel. Файлы ограничены 5 МБ. Перед загрузкой полученного файла требуется отдельное нажатие.
- Код комнаты проверяется до отправки; третьему участнику сервер отказывает. Ключ пользователя и код комнаты разведены по назначению.
- Тикет проверяется и в браузере, и на сервере. При сбое сохранения нет ложного подтверждения успеха.
- Выход из сессии объясняет потерю доступа без сохранённого ключа. Ключ скрыт визуально, копируется явным действием.
- Объяснение реальных ограничений WebRTC предшествует входу в комнату. UI не изображает фиктивную маршрутизацию, пропускную способность или число узлов.

## Доступность

Нативные кнопки и формы, подписи полей, заголовки, заметный keyboard focus, управление модальным окном с Escape и удержанием Tab внутри, текстовые сообщения об ошибках и `role=status` для результата. Статус обозначается текстом вместе с цветом. Адаптивная сетка; на телефонах меню открывается отдельной кнопкой. Поддержано prefers-reduced-motion. Окончательная оценка WCAG требует отдельного аудита контраста, скринридеров и реальных пользователей; сертификация не заявляется.

## Проверка удобства на защите

1. Новому пользователю предложить подключиться и найти способ пригласить друга без подсказок.
2. Второму пользователю предложить войти в комнату и обменяться сообщением/файлом.
3. Попросить сообщить об ошибке, найти ответ разработчика, закрыть и повторно открыть обращение.
4. Попросить сохранить доступ, восстановить его в приватном окне, объяснить разницу между ключом и кодом комнаты.
5. Повторить сценарии только с клавиатурой и на узком экране.

Измерять успешность задачи, время, число ошибочных действий и субъективную уверенность (1–5). Эти метрики предложены для исследования, а не выданы за уже собранные результаты.
